## 引言

我们开发的卡尔曼滤波器使用线性方程,因此滤波器只能处理线性问题。但世界是非线性的,所以我们一直研究到此为止的经典滤波器可能用途非常有限。

过程模型中可能存在非线性。假设我们想跟踪一个穿过大气层下落的物体。物体的加速度取决于它遇到的阻力。阻力取决于空气密度,而空气密度随高度降低。在一维中这可以用非线性微分方程建模

$$\ddot x = \frac{0.0034ge^{-x/22000}\dot x^2}{2\beta} - g$$

第二个非线性来源来自测量值。例如,雷达测量到物体的斜距,而我们通常对飞机在地面上方的位置感兴趣。我们使用勾股定理得到非线性方程:

$$x=\sqrt{\mathtt{slant}^2 - \mathtt{altitude}^2}$$

这些事实在卡尔曼滤波器的早期采用者看来并非未知。在 Kalman 博士发表他的论文后不久,人们就开始研究如何将卡尔曼滤波器扩展到非线性问题。

几乎可以说,任何人知道如何求解的唯一方程是 $\mathbf{Ax}=\mathbf{b}$。我们真正只知道如何做线性代数。我可以给你任何线性方程组,你要么能解决它,要么证明它没有解。

任何接受过数学或物理正规教育的人都花费了数年时间学习各种解析方法来求解积分、微分方程等。然而,即使是微不足道的物理系统也会产生无法解析求解的方程。我可以拿一个你能够积分的方程,插入一个 $\log$ 项,使其变得不可解。这导致了关于物理学家声称"假设一个无摩擦表面上的球形牛在真空中..."的笑话。如果不做极端的简化,大多数物理问题都没有解析解。

我们如何在计算机中模拟飞机上的气流,或预测天气,或用卡尔曼滤波器跟踪导弹? 我们退回到我们所知道的:$\mathbf{Ax}=\mathbf{b}$。我们找到某种方法将问题线性化,将其转换为一组线性方程,然后使用线性代数软件包计算近似解。

将非线性问题线性化会给我们不精确的答案,在像卡尔曼滤波器或天气跟踪系统这样的递归算法中,这些小误差有时会在每一步中相互加强,很快导致算法输出无意义的结果。

我们即将开始的是一个困难的问题。不再有一个明显的、正确的、数学上最优的解。我们将使用近似,我们将在计算中引入误差,我们将永远与*发散*的滤波器作斗争,即其数值误差压倒解的滤波器。

在本短章的其余部分,我将说明非线性卡尔曼滤波器面临的具体问题。只有在理解了问题中的非线性导致的特定问题后,你才能设计滤波器。随后的章节将教你如何设计和实现不同类型的非线性滤波器。

## 非线性的问题

卡尔曼滤波器的数学之所以美妙,部分原因是高斯方程如此特殊。它是非线性的,但当我们相加和相乘它们时,我们得到另一个高斯作为结果。这是非常罕见的。$\sin{x}*\sin{y}$ 不会产生 $\sin$ 作为输出。

我所说的线性可能是显而易见的,但有一些微妙之处。数学要求有两个:

* 可加性: $f(x+y) = f(x) + f(y)$
* 齐次性: $f(ax) = af(x)$


这导致我们说线性系统被定义为其输出与所有输入之和成线性比例的系统。其结果是,要成为线性的,如果输入为零,则输出也必须为零。考虑一个音频放大器 - 如果我对着麦克风唱歌,而你开始说话,输出应该是我们的声音(输入)之和乘以放大器增益。但如果放大器对零输入输出非零信号(如嗡嗡声),则加法关系不再成立。这是因为线性要求 $amp(voice) = amp(voice + 0)$。这显然应该给出相同的输出,但如果 amp(0) 非零,那么

$$
\begin{aligned}
amp(voice) &= amp(voice + 0) \\
&= amp(voice) + amp(0) \\
&= amp(voice) + non\_zero\_value
\end{aligned}
$$

这显然是无意义的。因此,一个看起来线性的方程,如

$$L(f(t)) = f(t) + 1$$

不是线性的,因为 $L(0) = 1$。要小心!

## 问题的直观理解

我特别喜欢以下看待问题的方式,我从 Dan Simon 的《最优状态估计》[[1]](#[1]) 中借用了它。考虑一个跟踪问题,我们获得目标的距离和方位,我们想跟踪它的位置。报告的距离是 50 km,报告的角度是 90$^\circ$。假设距离和角度的误差都以高斯方式分布。给定无限数量的测量值,位置的期望值是多少?

我一直建议使用直觉来获得洞察力,所以让我们看看它对这个问题的表现如何。我们可能会推理,由于距离的均值将是 50 km,角度的均值将是 90$^\circ$,因此答案将是 x=0 km, y=50 km。

让我们绘制它并找出答案。这里有 3000 个点,距离的正态分布为 0.4 km,角度的正态分布为 0.35 弧度。我们计算所有位置的平均值,并将其显示为星号。我们的直觉用一个大圆圈显示。

```python
import numpy as np
from numpy.random import randn
import matplotlib.pyplot as plt

N = 5000
a = np.pi/2. + (randn(N) * 0.35)
r = 50.0     + (randn(N) * 0.4)
xs = r * np.cos(a)
ys = r * np.sin(a)

plt.scatter(xs, ys, label='Sensor', color='k', 
            alpha=0.4, marker='.', s=1)
xmean, ymean = sum(xs) / N, sum(ys) / N
plt.scatter(0, 50, c='k', marker='o', s=200, label='Intuition')
plt.scatter(xmean, ymean, c='r', marker='*', s=200, label='Mean')
plt.axis('equal')
plt.legend();
```

我们可以看到我们的直觉让我们失望了,因为问题的非线性迫使所有误差在一个方向上产生偏差。这种偏差,经过多次迭代,可能导致卡尔曼滤波器发散。即使它没有发散,解也不会是最优的。应用于非线性问题的线性近似会产生不准确的结果。

## 非线性函数对高斯分布的影响

高斯分布在任意非线性函数下不封闭。回想卡尔曼滤波器的方程 - 在每次演化中,我们将表示状态的高斯通过过程函数传递以获得时间 $k$ 的高斯。我们的过程函数总是线性的,所以输出总是另一个高斯。让我们在图上看看这一点。我将取一个任意高斯并将其通过函数 $f(x) = 2x + 1$ 传递并绘制结果。我们知道如何解析地做到这一点,但让我们使用采样。我将生成 500,000 个具有正态分布的点,将它们通过 $f(x)$ 传递,并绘制结果。我这样做是因为下一个例子将是非线性的,我们将无法解析计算它。

```python
from numpy.random import normal

data = normal(loc=0., scale=1., size=500000)
plt.hist(2*data + 1, 1000);
```

这是一个不令人惊讶的结果。将高斯通过 $f(x)=2x+1$ 传递的结果是另一个以 1 为中心的高斯。让我们同时查看输入、非线性函数和输出。

```python
from kf_book.book_plots import set_figsize, figsize
from kf_book.nonlinear_plots import plot_nonlinear_func

def g1(x):
    return 2*x+1

plot_nonlinear_func(data, g1)
```

> 我在文件夹 Supporting_Notebooks 中的 Notebook *Computing_and_Plotting_PDFs* 中解释了如何绘制高斯分布等等。你也可以在[这里](https://github.com/rlabbe/Kalman-and-Bayesian-Filters-in-Python/blob/master/Supporting_Notebooks/Computing_and_plotting_PDFs.ipynb)[1]在线阅读它

标记为 'Input' 的图是原始数据的直方图。这通过函数 $f(x)=2x+1$ 传递,该函数显示在左下角的图表中。红线显示一个值 $x=0$ 如何通过函数传递。输入中的每个值都以相同的方式传递到右侧的输出函数。对于输出,我通过取所有点的平均值计算均值,并用虚线蓝线绘制结果。实线蓝线显示点 $x=0$ 的实际均值。输出看起来像高斯分布,实际上是高斯分布。我们可以看到输出中的方差大于输入中的方差,并且均值已从 0 移位到 1,这是我们给定传递函数 $f(x)=2x+1$ 所期望的。$2x$ 影响方差,$+1$ 移位均值。由虚线蓝线表示的计算均值几乎等于实际均值。如果我们在计算中使用更多点,我们可以任意接近实际值。

现在让我们看看一个非线性函数以及它如何影响概率分布。

```python
def g2(x):
    return (np.cos(3*(x/2 + 0.7))) * np.sin(0.3*x) - 1.6*x

plot_nonlinear_func(data, g2)
```

这个结果可能会让你有些惊讶。函数看起来"相当"线性,但输出的概率分布与高斯分布完全不同。回想乘以两个单变量高斯的方程:

$$\begin{aligned}
\mu &=\frac{\sigma_1^2 \mu_2 + \sigma_2^2 \mu_1} {\sigma_1^2 + \sigma_2^2} \\
\sigma &= \frac{1}{\frac{1}{\sigma_1^2} + \frac{1}{\sigma_2^2}}
\end{aligned}$$

这些方程对非高斯分布不成立,当然也不适用于上面 'Output' 图表中显示的概率分布。

这是查看相同数据作为散点图的另一种方式。

```python
N = 30000
plt.subplot(121)
plt.scatter(data[:N], range(N), alpha=.1, s=1.5)
plt.title('Input')
plt.subplot(122)
plt.title('Output')
plt.scatter(g2(data[:N]), range(N), alpha=.1, s=1.5);
```

原始数据显然是高斯的,但通过 `g2(x)` 传递的数据不再是正态分布的。在 -3 附近有一个厚带,点在带的两侧分布不均。如果你将此与前一张图中标记为 'output' 的 pdf 进行比较,你应该能够看到 pdf 形状如何与 `g(data)` 的分布匹配。

想想这对前一章的卡尔曼滤波器算法意味着什么。所有方程都假设通过过程函数传递的高斯结果是另一个高斯。如果这不成立,那么卡尔曼滤波器的所有假设和保证都不成立。让我们看看当我们再次通过函数传递输出时会发生什么,模拟卡尔曼滤波器的下一个时间步。

```python
y = g2(data)
plot_nonlinear_func(y, g2)
```

正如你所看到的,概率函数进一步偏离原始高斯。然而,图形仍然在 x=0 附近有些对称,让我们看看均值是什么。

```python
print('input  mean, variance: %.4f, %.4f' % 
      (np.mean(data), np.var(data)))
print('output mean, variance: %.4f, %.4f' % 
      (np.mean(y), np.var(y)))
```

让我们将其与通过 (-2,3) 和 (2,-3) 的线性函数进行比较,它非常接近我们绘制的非线性函数。使用直线方程我们有

$$m=\frac{-3-3}{2-(-2)}=-1.5$$

```python
def g3(x): 
    return -1.5 * x

plot_nonlinear_func(data, g3)
out = g3(data)
print('output mean, variance: %.4f, %.4f' % 
      (np.mean(out), np.var(out)))
```

尽管输出的形状非常不同,但每个的均值和方差几乎相同。这可能导致我们推理,如果非线性方程"接近"线性,也许我们可以忽略这个问题。为了测试这一点,我们可以迭代几次,然后比较结果。

```python
out = g3(data)
out2 = g2(data)

for i in range(10):
    out = g3(out)
    out2 = g2(out2)
print('linear    output mean, variance: %.4f, %.4f' % 
      (np.average(out), np.std(out)**2))
print('nonlinear output mean, variance: %.4f, %.4f' % 
      (np.average(out2), np.std(out2)**2))
```

不幸的是,非线性版本不稳定。它显著偏离均值 0,方差大半个数量级。

我通过使用一个非常接近直线的函数最小化了这个问题。如果函数是 $y(x)=-x^2$ 会发生什么?

```python
def g3(x): 
    return -x*x

data = normal(loc=1, scale=1, size=500000)
plot_nonlinear_func(data, g3)
```

尽管曲线在 $x=1$ 处是平滑的并且相当直,但输出的概率分布看起来一点也不像高斯,并且输出的计算均值与直接计算的值相差很大。这不是一个不寻常的函数 - 弹道物体沿抛物线运动,这是你的滤波器需要处理的那种非线性。如果你回想我们曾尝试跟踪一个球并惨遭失败。这张图应该让你深入了解为什么滤波器表现如此糟糕。

## 2D 示例

很难查看概率分布并推理滤波器中会发生什么。所以让我们考虑用雷达跟踪飞机。估计可能有一个看起来像这样的协方差:

```python
import kf_book.nonlinear_internal as nonlinear_internal

nonlinear_internal.plot1()
```

当我们尝试将这个问题线性化时会发生什么?雷达给我们到飞机的距离。假设雷达直接在飞机下方 (x=10),下一次测量指出飞机距离 3 英里 (y=3)。可以匹配该测量的位置形成一个半径为 3 英里的圆,如下所示。

```python

```

我们可以通过观察看到飞机的可能位置大约在 x=11.4, y=2.7 附近,因为那是协方差椭圆和距离测量重叠的地方。但距离测量是非线性的,所以我们必须将其线性化。我们还没有涵盖这个材料,但扩展卡尔曼滤波器将在飞机的最后位置 - (10,2) 处线性化。在 x=10 处,距离测量有 y=3,所以我们在该点线性化。

```python

```

现在我们有了问题的线性表示(字面上是一条直线),我们可以求解。不幸的是,你可以看到直线和协方差椭圆的交点距离实际飞机位置很远。

```python
nonlinear_internal.plot4()
```

那种误差通常会导致灾难性的结果。这个估计中的误差很大。但在滤波器的下一次创新中,这个非常糟糕的估计将被用来线性化下一个雷达测量,所以下一个估计可能比这个显著更差。仅仅几次迭代后,卡尔曼滤波器就会发散,并开始产生与现实没有对应关系的结果。

这个协方差椭圆跨越数英里。我夸大了尺寸以说明高度非线性系统的困难。在真实的雷达跟踪问题中,非线性通常没有那么糟糕,但误差仍然会累积。你可能使用的其他系统可能有这种程度的非线性 - 这不是为了说明一点而夸大的。在处理非线性系统时,你将始终与发散作斗争。

## 各种算法

你可能迫不及待想解决一个具体问题,并想知道使用哪个滤波器。我将快速调查各种选项。后续章节在某种程度上彼此独立,你可以有效地跳着读,尽管如果你真的想掌握所有材料,我建议线性阅读。

非线性滤波器的主力是*线性化卡尔曼滤波器*和*扩展卡尔曼滤波器*(EKF)。这两种技术是在 Kalman 发表他的论文后不久发明的,从那时起它们一直是主要使用的技术。飞机中的飞行软件,汽车或手机中的 GPS 几乎肯定使用这些技术之一。

然而,这些技术要求极高。EKF 在一点处线性化微分方程,这要求你找到偏导数矩阵(雅可比矩阵)的解。这可能很难或不可能解析地完成。如果不可能,你必须使用数值技术来找到雅可比矩阵,但这在计算上是昂贵的,并且会在系统中引入更多误差。最后,如果问题是相当非线性的,线性化会导致在每一步中引入大量误差,滤波器经常发散。你不能将一些方程扔到某个任意求解器中并期望得到好的结果。这对专业人士来说是一个困难的领域。我注意到,尽管 EKF 是现实世界应用中最常用的技术,但大多数卡尔曼滤波教科书只是简单地掠过 EKF。

最近该领域以令人兴奋的方式发生了变化。首先,计算能力已经增长到我们可以使用曾经超出超级计算机能力的技术的地步。这些使用*蒙特卡洛*技术 - 计算机生成数千到数万个随机点,并针对测量值测试所有这些点。然后它根据它们与测量值的匹配程度概率性地杀死或复制点。远离测量值的点不太可能被保留,而非常接近的点很可能被保留。经过几次迭代后,有一团粒子紧密跟踪你的物体,以及没有物体的地方有稀疏的点云。

这有两个好处。首先,即使对于极端非线性问题,算法也是稳健的。其次,算法可以同时跟踪任意多个物体 - 一些粒子将匹配一个物体的行为,其他粒子将匹配其他物体。所以这种技术经常用于跟踪汽车交通、人群中的人等等。

成本应该是清楚的。为滤波器中的每一步测试数万个点在计算上是昂贵的。但现代 CPU 非常快,这对 GPU 来说是一个好问题,因为算法的部分是可并行化的。另一个成本是答案不是数学的。使用卡尔曼滤波器,我的协方差矩阵给我关于估计中误差量的重要信息。粒子滤波器不给我严格的方法来计算这个。最后,滤波器的输出是一团点;然后我必须弄清楚如何解释它。通常你会做类似取点的均值和标准差的事情,但这是一个困难的问题。仍然有许多点不"属于"被跟踪的物体,所以你首先必须运行某种聚类算法来首先找到似乎在跟踪物体的点,然后你需要另一个算法从这些点产生状态估计。这些都不是难以处理的,但都是相当计算昂贵的。


最后,我们有一个叫做*无迹卡尔曼滤波器*(UKF)的新算法。它不要求你找到非线性方程的解析解,但几乎总是比 EKF 表现更好。它在非线性问题上表现良好 - EKF 有重大困难的问题。设计滤波器极其容易。有些人会说对 UKF 的评价仍未定论,但在我看来,UKF 在几乎所有方面都优于 EKF。我建议 UKF 应该是任何实现的起点,特别是如果你不是具有控制理论研究生学位的卡尔曼滤波器专业人士。主要缺点是 UKF 可能比 EKF 慢几倍,但这实际上取决于 EKF 是解析还是数值求解雅可比矩阵。如果是数值的,UKF 几乎肯定更快。尚未证明(可能无法证明)UKF 总是产生比 EKF 更准确的结果。在实践中它几乎总是这样做,通常显著如此。它非常容易理解和实现,我强烈建议将这个滤波器作为你的起点。

## 总结

世界是非线性的,但我们真正只知道如何解决线性问题。这为卡尔曼滤波器引入了重大困难。我们已经以 3 种不同但等效的方式研究了非线性如何影响滤波,我给了你主要方法的简要总结:线性化卡尔曼滤波器、扩展卡尔曼滤波器、无迹卡尔曼滤波器和粒子滤波器。

直到最近,线性化卡尔曼滤波器和 EKF 一直是解决这些问题的标准方法。它们非常难以理解和使用,而且它们也可能非常不稳定。

最近的发展提供了我认为更优越的方法。UKF 免除了寻找偏微分方程解的需要,但它通常也比 EKF 更准确。它易于使用和理解。我可以使用 FilterPy 在几分钟内让基本的 UKF 运行起来。粒子滤波器完全放弃数学建模,转而采用蒙特卡洛技术生成数千个点的随机云。它运行缓慢,但它可以相对容易地解决其他难以处理的问题。

我收到的关于 EKF 的电子邮件比其他任何东西都多;我怀疑这是因为书籍、论文和互联网上的大多数处理使用 EKF。如果你的兴趣在于掌握该领域,当然你会想了解 EKF。但如果你只是试图获得好的结果,我首先向你指出 UKF 和粒子滤波器。它们更容易实现、理解和使用,并且它们通常比 EKF 稳定得多。

有些人会对这个建议提出异议。许多最近的出版物致力于为给定问题比较 EKF、UKF 以及可能几个其他选择。你不需要为你的问题执行类似的比较吗?如果你正在向火星发送火箭,那么当然需要。你将平衡诸如准确性、舍入误差、发散、正确性的数学证明以及所需的计算工作等问题。我无法想象不深入了解 EKF。

另一方面,UKF 的表现非常出色!我在工作中将其用于现实世界的应用。我大多数情况下甚至没有尝试为这些应用实现 EKF,因为我可以验证 UKF 工作良好。是否有可能在某些情况下我可以从 EKF 中挤出另外 0.2% 的性能?当然!我在乎吗?不!我完全理解 UKF 实现,它易于测试和验证,我可以将代码传递给其他人并确信他们可以理解和修改它,而且我不是一个想在已经有工作解决方案时与困难方程作斗争的受虐狂。如果 UKF 或粒子滤波器开始对某些问题表现不佳,那么我将转向其他技术,但不会更早。而且实际上,UKF 通常在广泛的问题和条件范围内提供明显优于 EKF 的性能。如果"真的很好"已经足够好,我将把时间花在处理其他问题上。

我之所以详细阐述这一点,是因为在大多数教科书中 EKF 占据中心舞台,而 UKF 要么根本没有被提及,要么只是给出了 2 页的简单介绍,让你完全没有准备好使用滤波器。UKF 仍然相对较新,编写书籍的新版本需要时间。在许多书籍编写时,UKF 要么尚未被发现,要么只是一个未经证实但有前途的新奇事物。但当我现在写这篇文章时,UKF 已经取得了巨大成功,它需要在你的工具箱中。这就是我将花费大部分精力试图教你的东西。
