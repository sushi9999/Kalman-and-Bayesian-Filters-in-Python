## 引言

到目前为止,我们已经考虑了跟踪与我们的过程模型相关的表现良好的物体的问题。例如,我们可以使用恒速滤波器来跟踪沿直线移动的物体。只要物体以相当恒定的速度沿直线移动,或者非常缓慢地改变其轨迹和/或速度,这个滤波器就会表现得很好。相反,假设我们试图跟踪一个机动目标,例如道路上的汽车、飞行中的飞机等。在这些情况下,滤波器的表现相当差。或者,考虑一种情况,例如跟踪海洋中的帆船。即使我们对控制输入建模,我们也无法对风或洋流建模。

解决这个问题的一阶方法是使过程噪声 $\mathbf{Q}$ 更大,以解释系统动力学的不可预测性。虽然这可以在提供不发散滤波器的意义上起作用,但结果通常远非最优。较大的 $\mathbf{Q}$ 导致滤波器对测量中的噪声给予更多重视。我们很快就会看到这方面的例子。

在本章中,我们将讨论*自适应滤波器*的概念。当滤波器检测到过程模型无法解释的动力学时,滤波器将*适应*自己。我将从问题的示例开始,然后讨论和实现各种自适应滤波器。

## 机动目标

我们需要一个机动目标的模拟。我将实现一个带有转向输入的简单 2D 模型。你提供新的速度和/或方向,它将修改其状态以匹配。

```python
from math import sin, cos, radians

def angle_between(x, y):
  return min(y-x, y-x+360, y-x-360, key=abs)

class ManeuveringTarget(object): 
    def __init__(self, x0, y0, v0, heading):
        self.x = x0
        self.y = y0
        self.vel = v0
        self.hdg = heading
        
        self.cmd_vel = v0
        self.cmd_hdg = heading
        self.vel_step = 0
        self.hdg_step = 0
        self.vel_delta = 0
        self.hdg_delta = 0
    
    def update(self):
        vx = self.vel * cos(radians(90-self.hdg))
        vy = self.vel * sin(radians(90-self.hdg))
        self.x += vx
        self.y += vy
        
        if self.hdg_step > 0:
            self.hdg_step -= 1
            self.hdg += self.hdg_delta

        if self.vel_step > 0:
            self.vel_step -= 1
            self.vel += self.vel_delta
        return (self.x, self.y)

    def set_commanded_heading(self, hdg_degrees, steps):
        self.cmd_hdg = hdg_degrees
        self.hdg_delta = angle_between(self.cmd_hdg, 
                                       self.hdg) / steps
        if abs(self.hdg_delta) > 0:
            self.hdg_step = steps
        else:
            self.hdg_step = 0
         
    def set_commanded_speed(self, speed, steps):
        self.cmd_vel = speed
        self.vel_delta = (self.cmd_vel - self.vel) / steps
        if abs(self.vel_delta) > 0:
            self.vel_step = steps
        else:
            self.vel_step = 0    
```

现在让我们实现一个带有噪声的模拟传感器。

```python
from numpy.random import randn

class NoisySensor(object):
    def __init__(self, std_noise=1.):
        self.std = std_noise

    def sense(self, pos):
        """Pass in actual position as tuple (x, y).       
        Returns position with noise added (x,y)"""
        
        return (pos[0] + (randn() * self.std), 
                pos[1] + (randn() * self.std))
```

现在让我们生成一个轨迹并绘制它以测试一切是否正常工作。我将数据生成放在一个函数中,这样我们就可以创建不同长度的路径(为什么很快就会清楚)。

```python
import kf_book.book_plots as bp
import numpy as np
import matplotlib.pyplot as plt

def generate_data(steady_count, std):
    t = ManeuveringTarget(x0=0, y0=0, v0=0.3, heading=0)
    xs, ys = [], []

    for i in range(30):
        x, y = t.update()
        xs.append(x)
        ys.append(y)

    t.set_commanded_heading(310, 25)
    t.set_commanded_speed(1, 15)

    for i in range(steady_count):
        x, y = t.update()
        xs.append(x)
        ys.append(y)

    ns = NoisySensor(std)
    pos = np.array(list(zip(xs, ys)))
    zs = np.array([ns.sense(p) for p in pos])
    return pos, zs

sensor_std = 2.
track, zs = generate_data(50, sensor_std)

plt.plot(*zip(*track), color='b', label='track')
plt.axis('equal')

```

这种大量的噪声使我们能够更容易地看到各种设计选择的效果。

现在我们可以实现一个卡尔曼滤波器来跟踪这个物体。但让我们做一个简化。*x* 和 *y* 坐标是独立的,所以我们可以独立跟踪每个。在本章的其余部分,我们将只跟踪 *x* 坐标,以使代码和矩阵尽可能小。

我们从恒速滤波器开始。

```python
from filterpy.kalman import KalmanFilter
from filterpy.common import Q_discrete_white_noise

def make_cv_filter(dt, std):
    cvfilter = KalmanFilter(dim_x = 2, dim_z=1)
    cvfilter.x = np.array([0., 0.])
    cvfilter.P *= 3
    cvfilter.R *= std**2
    cvfilter.F = np.array([[1, dt],
                           [0,  1]], dtype=float)
    cvfilter.H = np.array([[1, 0]], dtype=float)
    cvfilter.Q = Q_discrete_white_noise(dim=2, dt=dt, var=0.02)
    return cvfilter

def initialize_filter(kf, std_R=None):
    """ helper function - we will be reinitialing the filter
    many times.
    """
    kf.x.fill(0.)
    kf.P = np.eye(kf.dim_x) * .1
    if std_R is not None:
        kf.R = np.eye(kf.dim_z) * std_R
```

现在我们运行它:

```python
sensor_std = 2.
dt = 0.1

# initialize filter
cvfilter = make_cv_filter(dt, sensor_std)
initialize_filter(cvfilter)

track, zs = generate_data(50, sensor_std)

# run it
z_xs = zs[:, 0]
kxs, _, _, _ = cvfilter.batch_filter(z_xs)

# plot results
bp.plot_track(track[:, 0], dt=dt)
bp.plot_filter(kxs[:, 0], dt=dt, label='KF')
bp.set_labels(title='Track vs KF', x='time (sec)', y='X');
plt.legend(loc=4);
```

我们可以从图中看到,卡尔曼滤波器无法跟踪航向的变化。回想一下 **g-h 滤波器**章节,这是因为滤波器没有对加速度建模,因此它将始终滞后于输入。如果信号进入稳态,滤波器最终会赶上信号。让我们看看这一点。

```python

track2, zs2 = generate_data(150, sensor_std)

bp.set_labels(title='Effects of Acceleration', 
              x='time (sec)', y='X')
```

潜在问题是我们的过程模型对于稳态部分是正确的,但对于物体机动时是不正确的。我们可以尝试通过增加 Q 的大小来解释这一点,如下所示。

```python
# reinitialize filter
dt = 0.1
initialize_filter(cvfilter)
cvfilter.Q = Q_discrete_white_noise(dim=2, dt=dt, var=2.0)
track, zs = generate_data(50, sensor_std)

# recompute track
kxs2, _, _, _ = cvfilter.batch_filter(z_xs2)
bp.plot_track(xs2, dt=dt)
bp.plot_filter(kxs2[:, 0], dt=dt, label='KF')
plt.legend(loc=4)
bp.set_labels(title='Large Q (var=2.0)', x='time (sec)', y='X')
```

我们可以看到,滤波器更快地重新获得了轨迹,但代价是输出中有很多噪声。此外,许多跟踪情况无法容忍在 4 到 8 秒之间显示的滞后量。我们可以进一步减少它,但代价是非常嘈杂的输出,如下所示:

机动意味着加速度,所以让我们实现一个恒加速度卡尔曼滤波器,看看它如何处理相同的数据。

```python
def make_ca_filter(dt, std):
    cafilter = KalmanFilter(dim_x=3, dim_z=1)
    cafilter.x = np.array([0., 0., 0.])
    cafilter.P *= 3
    cafilter.R *= std
    cafilter.Q = Q_discrete_white_noise(dim=3, dt=dt, var=0.02)
    cafilter.F = np.array([[1, dt, 0.5*dt*dt],
                           [0, 1,         dt], 
                           [0, 0,          1]])
    cafilter.H = np.array([[1., 0, 0]])
    return cafilter

def initialize_const_accel(f):
    f.x = np.array([0., 0., 0.])
    f.P = np.eye(3) * 3
```

```python
dt = 0.1
cafilter = make_ca_filter(dt, sensor_std)
initialize_const_accel(cafilter)

kxs2, _, _, _ = cafilter.batch_filter(z_xs2)

bp.plot_track(xs2, dt=dt)
bp.plot_filter(kxs2[:, 0], dt=dt, label='KF')
plt.legend(loc=4)
bp.set_labels(title='Constant Acceleration Kalman Filter',
              x='time (sec)', y='X')
```

恒加速度模型能够无滞后地跟踪机动,但代价是在稳态行为期间输出非常嘈杂。嘈杂的输出是由于滤波器无法区分机动的开始和信号中的噪声。信号中的噪声意味着加速度,因此滤波器的加速度项跟踪它。

似乎我们无法取胜。恒速滤波器在目标加速时无法快速反应,但恒加速度滤波器在零加速度情况下将噪声误解为加速度而不是噪声。

然而,这里有一个重要的见解,将引导我们找到解决方案。当目标不机动时(加速度为零),恒速滤波器表现最佳。当目标机动时,恒加速度滤波器表现良好,具有人为大的过程噪声 $\mathbf{Q}$ 的恒速滤波器也是如此。如果我们制作一个滤波器,使其适应被跟踪物体的行为,我们可以兼得两全其美。

## 检测机动

在我们讨论如何创建自适应滤波器之前,我们必须问"我们如何检测机动?"如果我们不知道机动何时发生,我们就无法合理地调整滤波器以响应机动。

我们一直将*机动*定义为被跟踪物体加速的时间,但一般来说,我们可以说,如果物体的行为与卡尔曼滤波器使用的过程模型不同,则物体相对于卡尔曼滤波器正在机动。

机动物体对滤波器的数学后果是什么?物体的行为将与滤波器预测的不同,因此残差将很大。回想一下,残差是滤波器的当前预测与测量之间的差异。
<img src="./figs/residual_chart.png">

为了确认这一点,让我们在机动期间绘制滤波器的残差。我将减少数据中的噪声量,以便更容易看到残差。

在左边,我绘制了噪声测量与卡尔曼滤波器输出的对比。在右边,我显示了滤波器计算的残差 - 测量与卡尔曼滤波器预测之间的差异。让我强调这一点以使其清楚。右边的图不仅仅是左边图中两条线之间的差异。左边的图显示了测量与最终卡尔曼滤波器输出之间的差异,而右边的图向我们显示了测量与*过程模型的预测*之间的差异。

这可能看起来像一个微妙的区别,但从图中你可以看到它不是。当机动开始时,左图中的偏差量很小,但右图中的偏差讲述了一个不同的故事。如果被跟踪物体按照过程模型移动,残差图应该在 0.0 附近波动。这是因为测量将遵循方程

$$\mathtt{measurement} = \mathtt{process\_model}(t) + \mathtt{noise}(t)$$

一旦目标开始机动,目标行为的预测将不匹配行为,因为方程将是

$$\mathtt{measurement} = \mathtt{process\_model}(t) + \mathtt{maneuver\_delta}(t) + \mathtt{noise}(t)$$

因此,如果残差偏离均值 0.0,我们就知道机动已经开始。

我们可以从残差图中看到,我们面临着艰巨的任务。我们可以清楚地看到残差图中机动的结果,但信号中的噪声量掩盖了机动的开始。这是我们从噪声中提取信号的老问题。

## 可调过程噪声

我们将考虑的第一种方法将使用较低阶模型并根据机动是否发生来调整过程噪声。当残差变得"大"时(对于某些合理的大的定义),我们将增加过程噪声。这将导致滤波器偏向测量而不是过程预测,滤波器将紧密跟踪信号。当残差很小时,我们将缩减过程噪声。

文献中有许多方法可以做到这一点,我将考虑几个选择。

### 连续调整

第一种方法(来自 Bar-Shalom [1])使用以下方程归一化残差的平方:

$$ \epsilon = \mathbf{y^\mathsf{T}S}^{-1}\mathbf{y}$$

其中 $\mathbf{y}$ 是残差,$\mathbf{S}$ 是系统不确定性(协方差),其方程为

$$\mathbf{S} = \mathbf{HPH^\mathsf{T}} + \mathbf{R}$$

如果用于计算这个的线性代数让你困惑,回想一下我们可以根据除法来考虑矩阵逆,因此 $\epsilon = \mathbf{y^\mathsf{T}S}^{-1}\mathbf{y}$ 可以被认为是计算

$$\epsilon\approx\frac{\mathbf{y}^2}{\mathbf{S}}$$

$\mathbf{y}$ 和 $\mathbf{S}$ 都是 `filterpy.KalmanFilter` 的属性,因此实现将很简单。

让我们看看 $\epsilon$ 随时间变化的图。

```python
from numpy.linalg import inv
dt = 0.1
sensor_std = 0.2
cvfilter= make_cv_filter(dt, sensor_std)
_, zs2 = generate_data(150, sensor_std)

epss = []
for z in zs2[:, 0]:
    cvfilter.predict()
    cvfilter.update([z])
    y, S = cvfilter.y, cvfilter.S
    eps = y.T @ inv(S) @ y
    epss.append(eps)

t = np.arange(0, len(epss) * dt, dt)
plt.plot(t, epss)
bp.set_labels(title='Epsilon vs time', 
              x='time (sec)', y='$\epsilon$')
```

这个图应该清楚地说明归一化残差的效果。对残差求平方确保信号始终大于零,通过测量协方差归一化缩放信号,以便我们可以区分残差相对于测量噪声何时明显改变。机动在 t=3 秒开始,我们可以看到 $\epsilon$ 在不久之后开始迅速增加。

一旦 $\epsilon$ 超过某个限制,我们将开始放大 $\mathbf{Q}$,一旦它再次低于该限制,我们将缩小它。我们将 $\mathbf{Q}$ 乘以一个缩放因子。也许有关于分析选择这个因子的文献;我通过实验推导它。我们可以对选择 $\epsilon$ 的限制(命名为 $\epsilon_{max}$)更加分析 - 一般来说,一旦残差大于 3 个标准差左右,我们就可以假设差异是由于真实变化而不是噪声。然而,传感器很少真正是高斯的,因此在实践中使用更大的数字,例如 5-6 个标准差。

我已经使用 $\epsilon_{max}$ 和 $\mathbf{Q}$ 缩放因子的合理值实现了这个算法。为了更容易检查结果,我将图限制为前 10 秒的模拟。

```python
# reinitialize filter
dt = 0.1
sensor_std = 0.2
cvfilter = make_cv_filter(dt, sensor_std)
_, zs2 = generate_data(180, sensor_std)

Q_scale_factor = 1000.
eps_max = 4.

xs, epss = [], []

count = 0
for i, z in zip(t, zs2[:, 0]):
    cvfilter.predict()
    cvfilter.update([z])
    y, S = cvfilter.y, cvfilter.S
    eps = y.T @ inv(S) @ y
    epss.append(eps)
    xs.append(cvfilter.x[0])

    if eps > eps_max:
        cvfilter.Q *= Q_scale_factor
        count += 1
    elif count > 0:
        cvfilter.Q /= Q_scale_factor
        count -= 1

bp.plot_measurements(zs2[:,0], dt=dt, label='z', alpha=0.5)
bp.plot_filter(t, xs, label='filter')
plt.legend(loc=4)
bp.set_labels(title='epsilon=4', x='time (sec)', y='$\epsilon$')
```

这个滤波器的性能明显优于恒速滤波器。恒速滤波器在机动开始后大约需要 10 秒才能重新获得信号。自适应滤波器在不到一秒的时间内就做到了同样的事情。

### 连续调整 - 标准差版本

另一种非常相似的方法来自 Zarchan [2],它根据测量误差协方差的标准差设置限制。这里的方程是:

$$ \begin{aligned}
std &= \sqrt{\mathbf{HPH}^\mathsf{T} + \mathbf{R}} \\
&= \sqrt{\mathbf{S}}
\end{aligned}
$$

如果残差的绝对值大于上面计算的标准差的某个倍数,我们将过程噪声增加一个固定量,重新计算 Q,然后继续。

```python
from math import sqrt

def zarchan_adaptive_filter(Q_scale_factor, std_scale, 
                            std_title=False,
                            Q_title=False):
    cvfilter = make_cv_filter(dt, std=0.2)
    pos2, zs2 = generate_data(180-30, std=0.2)
    xs2 = pos2[:,0]
    z_xs2 = zs2[:,0]

    # reinitialize filter
    initialize_filter(cvfilter)
    cvfilter.R = np.eye(1)*0.2

    phi = 0.02
    cvfilter.Q = Q_discrete_white_noise(dim=2, dt=dt, var=phi)
    xs, ys = [], []
    count = 0
    for z in z_xs2:
        cvfilter.predict()
        cvfilter.update([z])
        y = cvfilter.y
        S = cvfilter.S
        std = sqrt(S)

        xs.append(cvfilter.x)
        ys.append(y)

        if abs(y[0]) > std_scale*std:
            phi += Q_scale_factor
            cvfilter.Q = Q_discrete_white_noise(2, dt, phi)
            count += 1
        elif count > 0:
            phi -= Q_scale_factor
            cvfilter.Q = Q_discrete_white_noise(2, dt, phi)
            count -= 1

    xs = np.asarray(xs)
    plt.subplot(121)
    bp.plot_measurements(z_xs2, dt=dt, label='z')
    bp.plot_filter(xs[:, 0], dt=dt, lw=1.5)
    bp.set_labels(x='time (sec)', y='$\epsilon$')
    plt.legend(loc=2)
    if std_title:
        plt.title(f'position(std={std_scale})')
    elif Q_title:
        plt.title(f'position(Q scale={Q_scale_factor})')
    else:
        plt.title('position')
        
    plt.subplot(122)
    plt.plot(np.arange(0, len(xs)*dt, dt), xs[:, 1], lw=1.5)
    plt.xlabel('time (sec)')
    if std_title:
        plt.title(f'velocity(std={std_scale})')
    elif Q_title:
        plt.title(f'velocity(Q scale={Q_scale_factor})')
    else:
        plt.title('velocity')        
    plt.show()
 
zarchan_adaptive_filter(1000, 2, std_title=True)
```

所以我选择使用 1000 作为噪声的缩放因子,使用 2 作为标准差限制。为什么是这些数字?好吧,首先,让我们看看 2 和 3 个标准差之间的差异。

```python
zarchan_adaptive_filter(1000, 3, std_title=True)
```

我们可以从图表中看到,无论我们使用 2 个标准差还是 3 个标准差,位置的滤波器输出都非常相似。但速度的计算是另一回事。让我们进一步探讨这一点。首先,让我们使标准差非常小。

```python
zarchan_adaptive_filter(1000, .1, std_title=True)
zarchan_adaptive_filter(1000, 1, std_title=True)
```

随着标准差限制变小,速度的计算变得更糟。想想为什么会这样。如果我们开始改变滤波器,使其在残差甚至略微偏离预测时就偏向测量而不是预测,我们很快就会给测量几乎所有的权重。没有预测的权重,我们就没有信息来创建隐藏变量。因此,当限制为 0.1 std 时,你可以看到速度被测量中的噪声淹没。另一方面,因为我们非常偏向测量,位置几乎完美地跟随机动。

现在让我们看看过程噪声的各种增量的效果。这里我将标准差限制保持在 2 std,并将增量从 1 变化到 10,000。

```python
zarchan_adaptive_filter(1, 2, Q_title=True)
zarchan_adaptive_filter(10, 2, Q_title=True)
zarchan_adaptive_filter(100, 2, Q_title=True)
zarchan_adaptive_filter(1000, 2, Q_title=True)
zarchan_adaptive_filter(10000, 2, Q_title=True)
```

在这里我们可以看到,随着增量因子的增加,位置估计略有改善,但速度估计开始产生很大的超调。

我无法告诉你哪个是"正确的"。你需要根据真实和模拟数据测试滤波器的性能,并选择最符合你对每个状态变量性能需求的设计。
